# LowEndAFF 界面双审查

Method: dual-agent (A: /root/design_review_a · B: /root/technical_review_b)

日期：2026-11-09。范围：首页、100TB 测评、广告页、标签云；主要覆盖 1440px / 390px 与明暗主题，共 16 个基础组合，另检查了 320px 标签筛选空状态。应用源码基线为 `4a25b6a338e413c82249d1b70bdca0ea28b8b967`。用户要求先审查，不修改界面。

## 总体判断

保留现有设计，做局部阅读体验精修。Unslop 分类为 light polish，没有确认 P0 阻断或 P1 重大问题。地图、线路分组、国家标识与等宽数据构成了测评站自身的识别语言；Tokyo 双主题与紧凑布局协调，不需要重做 Hero、替换字体或清除国旗。

两名审查者分别检查视觉/阅读体验与检测器/技术证据；A 完成独立判断后，主审才读取 B 的发现并复核截图。以下三项均有浏览器证据，而非仅凭检测器规则判断。

## 优先问题

### 1. P2 — 文章目录出现得太晚

桌面 1440×1000 初始目录位于文档约 y=2355px，要先越过 Sponsors 与七张侧栏广告；手机 390×844 目录位于约 y=1065px，在顶部三张广告之后。读者想直接查线路或解锁结果时，快捷入口首先被藏到了后面。

建议桌面把 sticky 目录放到侧栏商业内容之前；手机把紧凑章节导航移到标题元信息之后、顶部广告之前。保留广告纵排、随机顺序与真实内容，不通过缩字或删除测试来缩短页面。手机目录 32px 开关、约 40.5px 链接可顺便统一到 44px 触控高度，属于可选的人体工学改进，不是已确认的可访问性违规。

位置：`src/layouts/ReviewLayout.astro:95`、`:121`；手机触控样式 `src/styles/editorial.css:702`、`:720`。
适用命令：`$impeccable layout`，需要时配合 `adapt`。
证据：`test-results/ui-review-a/article-390-light.png`、`behavior.json`、`interactions.json`；`test-results/ui-review-b/toc-open-390-light.png`。

### 2. P2 — 路由表缺少剩余内容的视觉提示

手机路由表可见区域约 352×358px，内容约 760×841px。横向藏着运营商和延迟列，纵向还有后续跳数；截图底部直接截断下一行，读者容易误以为数据到此结束。桌面也限制表格高度。

表格实际上可以用键盘及触摸滚动，问题是发现性。建议仅在实际溢出时提供清晰的滚动条或边缘渐隐，抵达边缘后相应消失；固定表头，必要时固定跳数列。保持原数据、字号、左对齐和紧凑结构。优先用视觉反馈，不额外堆叠用户此前不喜欢的说明文字。

位置：`src/styles/compact.css:446`、`:699`，`src/styles/editorial.css:561`，`src/components/mdx/BenchmarkResultsTable.astro:10`。
适用命令：`$impeccable clarify` / `polish`。
证据：`test-results/ui-review-a/article-route-390.png`、`article-route-1440.png`、`behavior.json`。

### 3. P2 — 桌面路由数量字号过小

电信、联通、移动等分类后面的 6、6、6、5、53 只有 10 CSS px，是有意义的线路数量，不只是装饰。建议提高为 12px 等宽数字，保留现有颜色和选中状态。手机目前隐藏这些数量，无须增加手机负担。

浅色实测对比度 4.58:1，深色 6.00:1；因此不是改颜色的问题，也不把 10px 宣称为某条最小字号标准违规。

位置：`src/styles/editorial.css:501`，`src/components/archive/RouteExplorer.astro:70`。
适用命令：`$impeccable typeset`。
证据：`test-results/ui-review-b/route-count-1440-light.png`、`final-measure.json`。

## 其他小项与明确排除

- “图片暂不可用”旁的“查看图片”略显矛盾；如果保留原图入口，可改成“尝试打开原图”。没有在本次审查重新请求外部图片，因此不作为新的外链故障结论。
- 标签页只有一篇文章时，筛选区显得偏重；未来内容增加会改变这一比例，本轮不建议据此重构筛选。
- 不建议恢复此前明确删除的“赞助推广／合作伙伴／赞助内容·产品详情以商家页面为准”文字。A 提出的广告可见标记建议经主审对照用户历史要求后排除。
- 不为检测器告警替换 Inter、删除章节编号、国旗 Emoji、地图循环、语义引用线或已确认的商业卡片。

## 值得保留

1. 真实内容驱动、测试分组和方向→运营商→城市线路的选择链路符合测评任务，路由选择能随 URL 保留并在刷新后恢复。
2. 手机表格保留可读字号，内容溢出限制在表格内；16 个基础组合没有页面横向溢出，320px 筛选空状态也可恢复。
3. 主题切换维持滚动位置 1700→1700；菜单 Escape、页签方向键、路由选择器键盘和广告箭头均通过抽样验证。广告箭头没有误触外链。

## 认知负荷与用户路径

整体低至中等，文章入口和宽表比较是主要额外负担。专业读者希望直接跳到回程或解锁，目录位置拖慢定位；手机读者必须自行发现表格的两个滚动方向；键盘用户的实测操作正常，不能据此报成无法访问。五类路由网络属于合理领域分组，不机械套用“四个选项”限制。

首页地图建立领域认同，进入文章后连续广告延后实际阅读入口；数据分组和选择器恢复控制感。文章结尾较长的商业内容是既有产品取舍，本轮不建议擅自删除或折叠。
